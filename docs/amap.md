# 高德接入与规划边界

## 配置

申请高德应用后，在 `.env` 分别设置 `AMAP_WEB_KEY`、`AMAP_JS_KEY`、`AMAP_JS_SECURITY_CODE`。前者为 Web 服务类型，后两项为 JS API 类型。不要将 Web 服务 Key 复制到前端代码、截图或公开仓库。

官方参考：

- [JS API](https://lbs.amap.com/api/javascript-api-v2/summary)
- [地点搜索](https://lbs.amap.com/api/webservice/guide/api/search)
- [路径规划 2.0](https://lbs.amap.com/api/webservice/guide/api/newroute)

应用使用高德提供的地点搜索和路径规划接口。酒店属于住宿地点类别，充电站属于汽车充电站类别；自驾和新能源均调用驾车路线，步行与骑行使用各自路线接口。接口的授权范围、服务配额和价格以你自己的高德控制台为准。

服务器将地点搜索结果短期缓存，按请求参数和凭证分区；道路计算也有缓存，降低重复调用。接口设置超时并隐藏含凭证的错误细节。只有 JS Key 会进入页面，必须设置合适的域名限制。JS 安全密钥由服务器的 /_AMapService 代理附加，不返回给浏览器。

## 无 Key 与失败回退

未配置高德时可以使用账号、路线库、行程编排、社区与文件导入导出。搜索不会返回伪造的酒店或充电站，可以手动输入地点及 GCJ-02 坐标。

缺少 Key、接口报错、配额用尽或单次规划时间过长时，尚未获得道路数据的路段会回退为带提示的直线估算。直线距离比可通行道路短，可能穿过不可通行区域；估算速度只是演示计算，不可作为出发时间、充电安全余量或实时导航依据。已取得道路数据的路段仍标明其来源。

内置模板的封面是本地插图，示意地图只是按坐标连接的轮廓，不是高德道路图或地理边界。

## 酒店衔接

将类型为“酒店”的地点放进某天后，当天最后一家酒店作为当晚终点，次日从上一天终点继续计算。酒店只是位置与备注：房价、房型、空房和订单均需到住宿平台确认。

## 新能源补能

填写满电续航后，系统按满电出发、预留 20% 电量估算可行距离。跨日保留剩余续航，加入充电停靠后按充满估算。对于超过估计可用续航的路段，系统提示添加补能，并在有高德道路数据时查询附近候选站。

候选不会自动变成实际行程点；用户需确认后添加。服务不接入车辆实时电量、充电运营商实时占用、枪口兼容性、价格、排队或预约，也不保证候选站的绕行可达性。天气、载重、山路会影响续航，长途行驶前应核实每次补能。

## 排查

- 只有示意地图：检查 JS Key / 安全密钥、浏览器网络、高德域名白名单及控制台报错。
- 地点搜索提示 Key 类型错误：`AMAP_WEB_KEY` 必须是 Web 服务 Key。
- 服务器 IP 不匹配：核查服务器出口 IP 与高德配置。
- 配额不足：查看高德控制台服务授权和配额，必要时等待恢复；项目不绕过配额限制。
- 修改 `.env` 没有生效：容器环境变量不会因 `restart` 自动刷新，使用 `docker compose up -d --force-recreate app`。生产环境同时传入两个 Compose 文件。
