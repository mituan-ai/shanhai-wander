# 数据、隐私与文件格式

## 持久化数据

默认数据保存在 `data/`；Docker 中是 `/app/data` 的独立命名卷。

| 内容 | 保存方式 |
| --- | --- |
| 账号及密码哈希 | SQLite；使用 Django 账号体系与密码校验 |
| 用户行程、公开状态、路线收藏 | SQLite，归属创建者 |
| 精选路线模板 | 仓库 JSON 导入到 SQLite，可由管理员维护 |
| 登录会话与高德缓存 | SQLite |
| 自动生成的应用密钥 | `.secret_key`，文件权限 0600 |
| 原始上传文件 | 不长期保存；解析后只保存允许的行程字段 |

应用不需要第三方账号登录或邮件服务。当前没有邮箱找回流程，可由管理员交互式重置密码。部署者可在后台管理用户和路线。

## 私密与公开

新建、复制和导入的行程均为私密。只有创建者能编辑、删除或改变公开状态；导入文件不能指定别人的 owner、数据库 ID、公开状态或账号字段。

公开后，任何访客都可查看路线、地点、住宿、日期、预算及备注，并可能下载或复制行程。发布前应删除家庭地址、个人联系方式、未出发的敏感行程等信息。取消公开会阻止后续访问原页面，但不删除他人已复制的副本。

模板收藏只供自己查看。站点管理员能通过管理后台处理用户数据与不合适内容。

## 第三方请求

地点搜索词、城市和坐标通过服务器发送给高德；道路计算发送各段起终点。浏览器还会按地图接入配置连接高德 JS 和地图服务。服务器 Web 服务 Key 不返回给前端，日志和客户端错误不应包含其原值。

没有高德配置时，应用不会伪造地点结果；使用本地模板、手动地点和明确标记的估算。

## JSON 格式

应用内采用 GCJ-02 坐标，文件需要明确声明版本与坐标系：

```json
{
  "schema_version": 1,
  "coordinate_system": "GCJ-02",
  "title": "我的周末旅行",
  "description": "带家人去湖边走走",
  "days": 2,
  "travel_mode": "driving",
  "stops": [
    {
      "id": "stop-1",
      "name": "千岛湖镇",
      "lng": 119.078234,
      "lat": 29.606922,
      "day": 1,
      "kind": "town",
      "stay_minutes": 60,
      "note": "先搜索确认停车位置",
      "address": "浙江省杭州市淳安县"
    },
    {
      "id": "stop-2",
      "name": "姜家镇",
      "lng": 118.663006,
      "lat": 29.477634,
      "day": 2,
      "kind": "town",
      "stay_minutes": 90,
      "note": "",
      "address": "浙江省杭州市淳安县"
    }
  ]
}
```

- `days`：1—30。
- `travel_mode`：`driving` / `ev` / `walking` / `cycling`。
- `kind`：`scenic` / `town` / `hotel` / `charging` / `custom`。
- `day`：地点所属天数，从 1 开始，不可超出 `days`。
- 坐标必须是有限数值；NaN、Infinity、重复 JSON 字段及不合法坐标会被拒绝。
- 上传最多 2 MB，点数和文本长度均有限制，具体见 `planner/services/validation.py`。
- 出发日期、预算和电动车续航不会从外部文件直接导入，请导入后在编辑器确认；文件中的权限与账号字段不会被采用。

原项目 JSON 的 schemaVersion 1/2 在已经包含完整地点坐标时可以尝试导入。尚未展开的路线模板引用会明确拒绝，不会默默丢失节点；需先在原工具或转换脚本中把引用展开为地点。

## GPX

GPX 标准地理坐标采用 WGS84。导入时转换为 GCJ-02，导出时反向转换，转换有近似误差。不要把 GCJ-02 直接标成 GPS 坐标，也不要重复转换。

导入优先读取路线点 `rtept`，其次轨迹点 `trkpt`，最后独立途经点 `wpt`，避免同一文件含多种点集时重复导入。长轨迹应先简化为行程关键途经点；该应用是行程规划器，不承担完整 GPS 轨迹分析。

应用自身导出的 GPX 在扩展字段里保留天数、停留时间、地点类型和地址。其他工具可能忽略这些扩展，重新导入后请确认日程安排。XML 外部实体和 DTD 会被拒绝，上传内容不能读取服务器文件。

## 添加维护者路线

在 `planner/data/routes.json` 中添加符合现有字段的对象，使用唯一 slug 和真实可核查的来源说明，然后运行 `python manage.py seed_routes`。路线源文件中的 GCJ-02 坐标必须标明属于近似锚点还是核验入口；不能将未核验的季节开放、里程或补给条件写成确定事实。

seed 使用事务和 `update_or_create`：重复执行不会产生重复模板，只更新对应 slug 的模板；不删除额外模板，也不接触用户行程。模板标题或节点改变后，已经复制到用户账号的行程保持独立。
